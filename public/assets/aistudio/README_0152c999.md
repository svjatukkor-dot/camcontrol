# CamControl

CamControl is an open-source, cross-platform desktop application for discovering, monitoring and eventually controlling cameras from Windows, Linux and macOS. The desktop backend is written in Rust and the desktop shell uses Tauri 2.

> **Status: early development.** The current implementation integrates native camera enumeration and an initial live preview through `nokhwa`. A user can select a discovered camera, open its stream, receive JPEG frames and stop the preview. Camera controls, mobile companion apps and full hardware validation are not implemented yet.

## Current functionality

- Native camera discovery using the operating system backend: Media Foundation on Windows, AVFoundation on macOS and Video4Linux on Linux (as provided by `nokhwa`).
- UI list of discovered local cameras and capture devices exposed by the OS.
- Initial live preview with start/stop commands and JPEG frame delivery through Tauri.
- Discovery diagnostic with explicit distinction between detection and stream testing.
- Rust unit tests for application metadata and diagnostic report structure.
- CI checks on Ubuntu, Windows and macOS.

Capture cards are discoverable only when their drivers expose them as compatible video devices (commonly UVC). HDMI input by itself does not guarantee compatibility.

## Planned support

| Device / connection | Planned approach | Important limitations |
|---|---|---|
| USB/UVC webcam | Native OS capture backend | Device and driver dependent |
| UVC capture card | Same local video backend | Must be exposed as a supported video device |
| Android over Wi-Fi | Dedicated Android companion app | Device-side app required for camera controls |
| Android over USB | Companion app and optional ADB-assisted setup | ADB is not a universal camera-control API |
| iPhone over Wi-Fi | Dedicated iOS companion app | Only controls exposed by the iOS app/AVFoundation can be offered |
| iPhone over USB | Research and supported vendor/app integration | Generic desktop USB camera control is not assumed |
| IP camera | ONVIF discovery and RTSP streaming | Depends on model, firmware and authentication |

## Architecture

- `src-tauri/` — Rust application backend and Tauri commands.
- `ui/` — HTML, CSS and JavaScript desktop interface.
- `docs/ROADMAP.md` — development milestones.
- `docs/TESTING.md` — automated and hardware test plan.
- `.github/workflows/ci.yml` — cross-platform CI checks.
- `.github/workflows/release-windows.yml` — automated Windows MSI/NSIS installer builds.

The application follows a capability-first model: controls must be queried from the device before being displayed as available. A setting must not be reported as applied until the device confirms the change or a documented read-back verifies it.

## Requirements

- Rust stable toolchain and Cargo.
- Node.js LTS (needed for future frontend tooling and Tauri CLI workflows).
- Tauri 2 platform prerequisites for the target OS. See the [official Tauri prerequisites](https://v2.tauri.app/start/prerequisites/).

## Build and test

From the repository root:

```bash
cargo fmt --all -- --check
cargo check --workspace --all-targets
cargo test --workspace
```

To run the desktop app after installing the Tauri CLI and platform dependencies:

```bash
cargo install tauri-cli --version '^2.0.0' --locked
cargo tauri dev
```

The app requires camera permission from the operating system. On Linux, access to the relevant `/dev/video*` device nodes may also be required.

## Windows installer builds

The `Windows installer` GitHub Actions workflow can be started manually from the Actions tab or automatically by pushing a Git tag matching `v*`. It builds MSI and NSIS EXE installers and attaches them to a GitHub Release for tag-triggered runs. The source must be hosted in a GitHub repository with Actions enabled.

For a local Windows build, install the Rust toolchain, Tauri CLI and Tauri 2 prerequisites, then run `cargo tauri build --bundles msi,nsis` from the repository root.

## Current diagnostic limitations

A successful discovery check means only that the native backend returned a list of devices. It does not test stream startup, frame delivery, FPS, focus, exposure, white balance, cable integrity or physical camera health. Those checks are planned separately.

## Security

Camera streams and pairing channels can expose sensitive video. Mobile pairing will require explicit user approval, authenticated sessions and local-network scope. The application will not expose an internet-facing control listener by default. Credentials must not be logged or stored in plaintext.
