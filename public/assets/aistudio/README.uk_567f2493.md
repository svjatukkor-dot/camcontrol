# CamControl

CamControl — кросплатформна настільна програма для виявлення, моніторингу та майбутнього керування камерами у Windows, Linux і macOS. Backend написаний на Rust, графічна оболонка — Tauri 2.

> **Стан: рання розробка.** Поточна версія використовує `nokhwa` для пошуку локальних камер і початкового відеоперегляду. Можна вибрати знайдену камеру, відкрити потік, отримувати JPEG-кадри та зупинити перегляд. Керування параметрами камер, мобільні компаньйони й повна перевірка обладнання ще не реалізовані.

## Реалізовано

- Виявлення камер через нативні backend-и ОС: Media Foundation у Windows, AVFoundation у macOS та Video4Linux у Linux (у межах підтримки `nokhwa`).
- Відображення знайдених локальних камер та сумісних пристроїв відеозахоплення.
- Початковий відеоперегляд: запуск/зупинка потоку та отримання кадрів через Tauri-команди.
- Діагностика, яка відокремлює факт виявлення від перевірки відеопотоку.
- Початкові Rust unit-тести.
- CI-перевірки на Ubuntu, Windows та macOS.

Карти відеозахоплення будуть видимі лише тоді, коли драйвер ОС представляє їх як сумісні відеопристрої (наприклад, UVC). Сам факт наявності HDMI-входу сумісності не гарантує.

## Заплановано

| Пристрій / підключення | Підхід | Обмеження |
|---|---|---|
| USB/UVC-камера | Нативний backend ОС | Залежить від пристрою та драйвера |
| UVC capture card | Той самий backend локального відео | ОС має бачити карту як відеопристрій |
| Android через Wi-Fi | Окремий застосунок-компаньйон | Для керування камерою потрібен застосунок на телефоні |
| Android через USB | Компаньйон та, за потреби, ADB | ADB не є універсальним API керування камерою |
| iPhone через Wi-Fi | Окремий iOS-компаньйон | Доступні лише параметри, які відкриває iOS-застосунок |
| iPhone через USB | Дослідження сумісних vendor/app інтеграцій | Універсальне USB-керування не передбачається |
| IP-камера | ONVIF та RTSP | Залежить від моделі, прошивки й автентифікації |

## Структура

- `src-tauri/` — Rust backend та команди Tauri.
- `ui/` — HTML, CSS та JavaScript інтерфейс.
- `docs/ROADMAP.md` — етапи розробки.
- `docs/TESTING.md` — автоматизовані та апаратні тести.
- `.github/workflows/ci.yml` — CI для трьох ОС.
- `.github/workflows/release-windows.yml` — автоматична Windows-збірка інсталятора MSI/NSIS за тегом або вручну.

## Вимоги

- Rust stable та Cargo.
- Node.js LTS.
- Системні залежності Tauri 2 для цільової ОС. Див. [офіційні вимоги Tauri](https://v2.tauri.app/start/prerequisites/).

## Збірка та тести

У корені репозиторію:

```bash
cargo fmt --all -- --check
cargo check --workspace --all-targets
cargo test --workspace
```

Для запуску після встановлення Tauri CLI та системних залежностей:

```bash
cargo install tauri-cli --version '^2.0.0' --locked
cargo tauri dev
```

Надайте програмі дозвіл на доступ до камери в налаштуваннях приватності ОС. У Linux також може знадобитися доступ до відповідного `/dev/video*`.

## Збірка Windows-інсталятора

GitHub Actions workflow `Windows installer` запускається вручну з вкладки Actions або автоматично після push Git-тега формату `v*`. Він збирає MSI та NSIS EXE-інсталятор і додає їх до GitHub Release для тегованих запусків. Для цього код має бути у GitHub-репозиторії з увімкненими Actions.

Локально Windows-збірка виконується командою `cargo tauri build --bundles msi,nsis` після встановлення Rust, Tauri CLI та системних передумов Tauri 2.

## Межі поточної діагностики

Успішне виявлення означає лише, що backend повернув список пристроїв. Це не перевіряє запуск відеопотоку, доставку кадрів, FPS, фокус, експозицію, баланс білого, цілісність кабелю чи фізичний стан камери.

## Безпека

Відеопотоки та канали сполучення можуть містити приватні дані. Майбутнє сполучення з телефоном вимагатиме явного підтвердження користувача, автентифікованих сесій та обмеження локальною мережею. За замовчуванням програма не повинна відкривати керування з інтернету. Паролі не можна записувати в логи або зберігати у відкритому вигляді.
